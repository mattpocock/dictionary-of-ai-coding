---
term: Stateless
description: คุณสมบัติไม่มีการส่งต่อหรือเก็บจำข้อมูลข้ามรอบการทำงาน โดย model และ agent จะทำงานแบบนี้เป็นค่าเริ่มต้น
---

ไม่มีการส่งต่อหรือเก็บข้อมูลไปข้างหน้า ตัว [model](./Model.md) จะทำงานแบบ stateless ข้ามหน่วยคำขอผู้ให้บริการ ([model provider requests](./Model%20provider%20request.md)) ซึ่งในทุก ๆ คำขอระบบจำเป็นต้องส่งข้อมูลในพื้นที่หน้าต่างบริบท ([context window](./Context%20window.md)) กลับไปทั้งหมด เพราะโมเดลไม่มีช่องทางอื่นในการมองเห็นข้อมูลภายนอกเลย ส่วนตัว [agent](./Agent.md) โดยปกติแล้วจะทำงานแบบ stateless ข้ามแต่ละ [session](./Session.md) โดยเริ่มต้น หมายความว่าเมื่อเปิดเซสชันใหม่จะไม่มีร่องรอยของการพูดคุยเก่าหลงเหลืออยู่เลย ซึ่งเป็นคำตรงข้ามกับ [stateful](./Stateful.md)

ตัวโมเดลเองนั้นมีคุณสมบัติเป็นแบบ stateless อย่างถาวร เนื่องจากค่าพารามิเตอร์ ([parameters](./Parameters.md)) ทั้งหมดจะถูกแช่แข็งไว้อย่างตายตัวตั้งแต่หลังขั้นตอนการฝึกฝน ([training](./Training.md)) และไม่มีสิ่งใดที่คุณทำในช่วงเวลาของการนำไปใช้งานหรือ [การอนุมาน](./Inference.md) ที่จะไปเปลี่ยนแปลงตัวเลขเหล่านั้นได้ โมเดลจึงไม่สามารถเรียนรู้จากคำตักเตือนแก้ไขของคุณ ไม่สามารถจดจำเรื่องที่คุณเคยบอกไปเมื่อวานนี้ และไม่เคยทำความรู้จักตัวตนของคุณเลย แม้ว่าลักษณะของบทสนทนาจะทำให้เราชวนรู้สึกไปเองเช่นนั้นก็ตาม ความต่อเนื่องที่คุณสัมผัสได้ภายในเซสชันนั้นเป็นสิ่งถูกสร้างขึ้นมาเลียนแบบโดยระบบควบคุม ([harness](./Harness.md)) ซึ่งทำหน้าที่เก็บรักษาประวัติบันทึกการพูดคุยและส่งมันกลับไปพร้อมกับทุก ๆ request สรุปคือโมเดลไม่ได้จำบทสนทนาได้ แต่มันเป็นการอ่านประวัติทั้งหมดใหม่อีกรอบต่างหาก

ผลลัพธ์ในทางปฏิบัติคือ หากคุณต้องการให้ระบบจดจำสิ่งใดข้ามเซสชัน คุณจำเป็นต้องบันทึกข้อมูลนั้นลงในพื้นที่บางจุดที่ agent สามารถอ่านกลับเข้ามาได้ ซึ่งนั่นคือบทบาทของไฟล์คู่มือประจำตัวโปรเจกต์ (เช่น AGENTS.md) [ระบบความจำ](./Memory%20system.md) หรือไฟล์บันทึกส่งงาน (handoff artifacts) ซึ่งเป็นไฟล์ที่จะถูกโหลดเข้าสู่ [บริบท](./Context.md) ของเซสชันในอนาคต เพื่อทำหน้าที่แทนระบบความจำที่ตัวโมเดลไม่มี ดังนั้นเวลาที่ agent ยังคงทำผิดพลาดในเรื่องเดิม ๆ ทั้งที่คุณเคยแก้ไขไปแล้ว คำถามหลักจึงไม่ใช่เรื่องทำไมมันถึงไม่ยอมเรียนรู้ (เพราะมันไม่มีความสามารถนั้นอยู่แล้ว) แต่ต้องถามว่าเราควรเขียนคำดัดแปลงแก้ไขนั้นลงในไฟล์ไหน เพื่อให้ทุกเซสชันในอนาคตเปิดอ่านและทำตามได้อย่างถูกต้อง

_ตัวอย่างการใช้งาน:_

"ทำไมพอล้างประวัติการคุย ([clear](./Clearing.md)) ทีไร มันชอบลืมข้อตกลงในการเขียนโค้ดของเราทุกทีเลยล่ะครับ"

"เพราะโมเดลมันเป็นแบบ stateless ครับ พอเริ่มเซสชันใหม่ข้อมูลก็หายเกลี้ยง ถ้าอยากให้มันจำได้ตลอด ต้องเอาข้อตกลงไปเขียนไว้ในไฟล์ AGENTS.md หรือเซฟลงไฟล์ความจำ เพื่อให้ตัว harness คอยโหลดเข้าระบบตอนเริ่มเซสชันครับ"
